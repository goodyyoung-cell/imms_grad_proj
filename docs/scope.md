# 이번 학기 구현 범위

작성: 2026-11-21 · 상태: **초안 (팀 리뷰 필요)**

**최종 제출 마감: 2026-12-03(목).** 남은 기간이 약 12일이고 그 안에 구현, 평가, 보고서를 모두 끝내야 한다. 5개 모듈을 같은 깊이로 만들 수 없으므로, 무엇을 끝까지 만들고 무엇을 줄이는지 정한다.

## 원칙

- **루프 하나를 끝까지.** 리드 한 건이 유입에서 인계까지 실제로 흘러가는 경로 하나를 완성하는 것이 기능 여러 개를 반쯤 만드는 것보다 낫다.
- **고객 접점은 사람 승인, 내부 작업은 자율.** 이 경계가 에이전트 설계의 핵심 주장이므로 모든 모듈에 똑같이 적용한다.
- **평가 가능한 형태로 만든다.** 모든 실행은 로그(어떤 도구를 왜 골랐는지, 무엇이 승인됐는지)를 남겨 평가와 보고서에 쓴다.

## 핵심 루프

```
유입 → ① 리서치(자율 루프) → ② 우선순위(규칙 점수 + 근거)
     → ③ 메일 초안 → [사람 승인] → ④ 발송(샌드박스) → ⑤ 답장 관찰·분류
     → 후속 제안 → [사람 승인] → … → ⑥ 인계 요약
```

## 모듈별 범위

| # | 모듈 | 구분 | 이번 학기에 만드는 것 | 만들지 않는 것 |
|---|------|------|----------------------|----------------|
| 1 | 고객 리서치·선별 | **P0** | 에이전트가 DART·홈페이지·뉴스 중 출처를 골라 빈칸을 채우는 루프. 규칙 기반 점수와 근거 태그. 출처 없는 사실은 버림 | LLM이 점수를 직접 매기는 방식, 유료 데이터베이스 연동 |
| 2 | 이메일 소통 | **P0** | RAG 근거 기반 초안, 사람 승인 후 샌드박스 발송, 답장 분류(수신 거부 즉시 중단, 애매하면 이관), 무응답 시 후속 제안 | 실제 고객 대상 발송, 사람 승인 없는 자동 발송 |
| 4 | 인간 SDR 인계 | **P0** | 리서치·접촉 이력·선별 근거·권장 후속 조치를 한 장으로 요약해 담당자에게 전달 | CRM 연동 |
| 3 | 초기 스크리닝 콜 | **축소** | 메일 CTA의 예약 링크와, 인계 요약 안의 **"스크리닝에서 확인할 질문"** 목록 (도입 목적·사용 환경·의사결정 구조·도입 시점). 시간이 남으면 텍스트 모의 스크리닝 | 실시간 음성 응대, 화상 미팅 플랫폼 실연동 |
| 5 | 모의 콜·코칭 | **보고서 설계안** | 보고서에 설계(입력, 역할극 흐름, 4개 피드백 기준)만 담는다. 구현은 하지 않는다 | 구현 전체 |

공통 P0:
- **RAG 지식베이스**: 가상 제품 자료(소개, 가격 정책, FAQ, 반대 의견 대응) 소량. 근거가 없으면 모른다고 하고 사람에게 넘긴다.
- **평가 도구**: 같은 시나리오를 수작업과 에이전트로 처리해 비교하는 스크립트와 실행 로그.
- **샘플 데이터**: 가상·비식별 리드 데이터 (중복, 직급 표기 다양성, 비상장사 포함).

## 일정이 밀릴 때 내리는 순서

1. 뉴스 검색을 빼고 DART·홈페이지만 쓴다.
2. 후속 제안을 빼고, 답장 분류(수신 거부 중단, 애매하면 이관)까지만 둔다.
3. 메신저 승인 대신 관리 화면의 승인 버튼으로 대신한다.

Cloud Run 배포는 필수라 이 목록에 넣지 않는다. 대신 11/22에 뼈대를 먼저 배포해 배포 문제를 일찍 드러낸다.
